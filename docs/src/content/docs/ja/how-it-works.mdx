```
xn init ─▶ xn data add ─▶ xn doctor ─▶ xn train ─▶ runs/default/ckpt.pt ─▶ xn generate
```

`xn` は Rust 製のネイティブバイナリです。`init` と `doctor` のうち環境確認の部分は自分で処理し、`data`・`train`・`generate` は `uv run --project <エンジン> python -m xn ...` として Python エンジンに渡します。エンジンは `src/xn/` にあります。

## 学習（`xn train`）

中心は `src/xn/train.py` の `train()` です。

<Steps>

1. **データを読み込む**（`loader.py`）。`content_loader` に該当するファイルを全部読み、ドキュメントのリストにします。まったく同じ内容のドキュメントは 1 つにまとめます。

2. **学習用と検証用に分ける**（`split_docs`）。ドキュメントの最後の `val_fraction` を検証用に取り分けます。学習した文章そのものでテストされることはありません。ドキュメントが少なすぎる場合は、文章の最後の部分を使います。

3. **トークナイザを作る**（`tokenizer.py`）。`"bpe"` の場合、学習用の文章でいちばんよく隣り合うバイト列の組を結合する処理を、語彙が `vocab_size` 個になるまで繰り返します。使うのは学習用の文章だけです。

4. **文章を数値にする**。文章全体を、トークン ID の長い列に変換します。

5. **学習ループを回す**。`max_steps` 回繰り返します（下記）。

6. **検証と保存**。`eval_interval` ステップごとに検証用データで loss を測ります。過去最良なら、設定・重み・トークナイザをまとめて `ckpt.pt` に保存します。

</Steps>

### 学習ループの 1 ステップ

1. **バッチを切り出す**（`get_batch`）。列のランダムな位置から `block_size` トークンずつ、`batch_size` 本を切り出します。正解は、同じ範囲を 1 トークン右にずらしたものです。

   ```
   入力 x: 吾輩 は 猫 で ある
   正解 y: は 猫 で ある 。
   ```

2. **予測する**（`model.py` の `GPT.forward`）。トークンをベクトルにして位置の情報を足し、Transformer の層を `n_layer` 段通します。各層は、前の文脈だけを参照するアテンションと、MLP でできています。最後に、各位置で「次に来るトークン」の確率を出します。

3. **誤差を測る**。cross-entropy で計算します。正解のトークンに付けた確率が低いほど、loss が大きくなります。

4. **重みを直す**。誤差逆伝播で、loss を減らすには各重みをどちらへ動かせばよいかを求めます。勾配の大きさを抑えて（勾配クリッピング）から、AdamW で重みを少し動かします。

5. **学習率を調整する**（`lr_at`）。最初の `warmup_steps` で徐々に上げ、その後はコサイン曲線で `min_lr` まで下げます。

## 生成（`xn generate`）

中心は `model.py` の `GPT.generate` です。

<Steps>

1. **読み込む**（`load_checkpoint`）。`ckpt.pt` の設定からモデルを作り直し、重みとトークナイザを復元します。

2. **プロンプトを変換する**。先に末尾の空白と改行を取り除きます。モデルは「改行＋次の行のインデント」を 1 トークンとして覚えているので、それはモデル自身に出させるためです。

3. **1 トークンずつ生成する**。`max_new_tokens` 回繰り返します。
   1. 直近の `block_size` トークンをモデルに入れ、次のトークンの確率を取り出す
   2. 直近 `repetition_window` トークンに出てきたトークンの点数を下げる（`repetition_penalty`）
   3. `temperature` で割る。低いほど無難、高いほど冒険的になる
   4. 確率の高い上位 `top_k` 個だけを残す
   5. 確率に従って 1 つ選び、列の末尾に足す

4. **文字に戻す**。トークン ID の列をバイト列に戻し、UTF-8 の文字にします。

</Steps>

## ポイント

モデルが学ぶのは「この文脈の次に、どのトークンがどのくらいの確率で来るか」だけです。生成は、その確率に従ってトークンを 1 つずつ選んで並べていく作業にすぎません。どこまで学べるかは、データの量とモデルの大きさで決まります。既定のモデルは約 90 万パラメータです。
